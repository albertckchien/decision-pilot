## 用戶 2026-11-08 改：初階報告也收點數

開了 API 以後，問題卡每張都要花錢，所以：
- **先註冊才寫**：用 Email 註冊、收驗證碼才算開好帳號，一個 Email 一個帳號。
- **新帳號只送一次 10 點**（不是每天送），剛好夠一份初階報告（點數表的概述 10 點），做不了分析（50）和完整（100）。
- 分析、完整報告要另外買點數；付款還沒做，試跑期間點完 10 點後顯示「付費版還在準備，開放時寄信通知你」。
- 讀書會同學用你發的測試帳號（第 3 項），帳號裡先存夠跑分析或完整報告的點數，不受這條限制。

## 路人會經歷什麼（照上面改過）

1. 首頁講清楚這是什麼、看兩份範例報告；按「開始」→ 用 Email 註冊（收驗證碼）→ 帳號裡有 10 點。
   然後一個大輸入框：「把你卡住的事寫下來」（50～1,000 字）。
2. 送出後 10～20 秒：畫面出現**問題卡**（重述一句、要決定的事、A 和 B 和各自的代價、哪一種兩難），可以直接改。
3. 補 3～4 個 ★ 題（照兩難型態，選擇題為主），按「用 10 點看初階報告」，扣點。
4. 當場出現**初步分析**（照 `overview_template.md`，規則產生，不再用模型）：
   - 準備度體檢（財務、能力和資源、家人和外部，高中低＋一句）
   - 這類兩難最常讓人後悔的 3 件事
   - 做決定前先確認的 3 件事
   - 目標國家的大環境快照（200 國資料已經有）
   - 這類兩難常有人走的另一條路（2～3 行）
5. 看完才出現：分析、完整報告多了什麼，和「想知道該選哪個？買點數看分析報告」（試跑期間顯示還在準備）。

## 需要你先決定的

1. **開 Anthropic API 帳戶**：這是唯一要花錢的地方。概述範本估每張問題卡約 1 元；試跑期間設全站每天上限就能控制總額。帳戶要你自己開、自己綁卡、自己產金鑰（我不能代填付款資料和金鑰），再把金鑰貼進 Apps Script 的 Script Properties。
   - 不開 API 的替代做法：路人寫完先拿到「我們收到了」，工作人員用訂閱額度跑問題卡，幾小時後寄連結。這樣就不是「當場」，但完全不花錢。
2. **段落庫要寫多少**：照範本全寫，5 種兩難大約 150～200 段；也可以先只做「走還是留」和「擴大還是守住」兩種（讀書會同學最常見），其他型態先顯示「這類兩難的初步分析還在準備」。

## Haiku 試做問題卡（2026-11-08）

拿 4 個測試情境的自由描述（轉行工程師、軟體新創、家族餐飲、派駐新加坡），用 haiku 子代理照 `intake_form.md` 第零步整理成問題卡（JSON），跟手工版的問題卡欄位比。

| 項目 | 結果 |
|---|---|
| 兩難型態 | 4／4 判對 |
| A、B 和代價 | 4 張都跟手工版對得上，沒有編出用戶沒寫的事；評價詞（沒興趣、很穩定）沒寫進選項和代價 |
| 缺的資料 | 比手工版還細，而且抓到的都是會讓結論翻的：例如轉行情境抓到「現職有沒有分紅或年終」（手工報告最大的代價就在這裡）、家族餐飲抓到「兒子本人想不想接」、派駐抓到「35% 是稅前還是稅後」（新加的基準規則有照做） |
| 沒做好的 | 重述超過三句（2 張）；軟體新創把「最在意的事」（目標排序）放進「你最擔心的事」欄；少數代價句有一點推論（「要邊做邊補」） |

結論：Haiku 做這一步夠用。沒做好的三項用程式擋（欄位字數上限、欄位內容檢查），加上問題卡本來就給用戶看、可以改。手工版有的「35 歲要轉越來越難」這類話，是用戶在表單裡多寫的，自由描述裡沒有，不算 Haiku 漏。
注意：這次是在 Claude Code 裡用 haiku 子代理跑，正式版走 API 時提示詞要直接帶進去（子代理是自己讀檔），上線前用 API 再試一次同樣 4 個情境。

## 純規則 vs Haiku（同樣 4 段自由描述）

用戶指出應該跟「照規則走」比。寫了一支純規則程式（關鍵字分型、句型抓選項、照型態固定的缺資料清單，不用模型），對同樣 4 段描述跑。關鍵字是看過這 4 個情境才寫的，對規則版偏有利。

| 欄位 | 純規則 | Haiku |
|---|---|---|
| 兩難型態 | 4／4 對（但關鍵字是照這 4 個情境挑的） | 4／4 對 |
| A、B | 1／4 能用。轉行：B 變成「不offer，職稱是…」；餐飲：完全漏掉「交給兒子」，A、B 都在講外聘；派駐：B 抓到擔心的那句話 | 4／4 能用 |
| A、B 的代價 | 抓不到（規則沒辦法判斷哪句是代價） | 4／4 有，跟手工版對得上 |
| 要決定的時間 | 3／4（餐飲的「明年 1 月尾牙」抓不到） | 4／4 |
| 你最擔心的事 | 2／4 | 4／4（1 張放錯成目標排序） |
| 缺的資料 | 照型態列固定清單，會問用戶已經寫過的（餐飲問「其他人服不服」，原文寫了店長不服），也會問不相關的（派駐問「新技能有幾成」） | 針對這個人缺的，會讓結論翻的 |
| 重述 | 只是原文第一句 | 三句重述（2 張超長） |

結論：純規則只做得到分型和一部分期限；選項、代價、缺的資料這三個最重要的欄位做不出來。要不用模型，就只能讓用戶自己填表單（選型態、填 A、B 和代價），也就是回到「一上來先填一堆欄位」。Haiku 這一步值得花。
