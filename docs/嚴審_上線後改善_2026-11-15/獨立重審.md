# 獨立重審：再活一次新功能（2026-11-15）

驗證方式：`node check.js 1000`（全過）、自寫 node 腳本照 ui.js 的 runPath 重跑幾百局、本機開頁面用瀏覽器量 computed style。

## 1. 「跳過」第一局也看得到，抽完還在【擋上線】已驗證
- play/index.html:42 `<button class="btn quiet skiproll" hidden>`；assets/site.css:69 `.btn { display: inline-flex }`
- 作者樣式蓋掉 `hidden`。實測 `hidden=true` 但 display 是 inline-flex，出生卡出來後按鈕還在（68×54），按了沒反應。ui.js:56「第一局保留懸念」沒做到。
- 改法：site.css 加 `[hidden] { display: none !important; }`。

## 2. 分享網址框一直開著，換局也不清【該修】已驗證（顯示）／推論（殘留）
- play.css:139 `.share-url { display: block; ... }`，原因跟第 1 條一樣，結局頁一直有個空白輸入框。
- 手動複製失敗那次填進去的網址，end() 只清 share-msg（ui.js:209），下一局還留著上一局的連結。
- 改法：同第 1 條；end() 加上 `$('share-url').hidden = true; value = ''`。

## 3. 分岔後沿用「第一次的選法」，結婚常常被改沒了【該修】已驗證
- ui.js:217 `if (!(x.id in prefer)) prefer[x.id] = x.k;`
- 同一種抉擇出現好幾次時只記第一次。玩家結婚卡先選「還不想」、後來選「結婚」，分岔到更早的抉擇時，系統每次都選「還不想」，問滿就變單身。300 局裡有 23 局是這種情況，23 局的另一條路全部沒結婚。下方對照表的「家庭」和「不一樣的事」會把這個差別算成那個抉擇造成的。
- 改法：記最後一次的選法，或照出現順序對應（第 n 次結婚卡用第 n 次的選法）。

## 4. 兩邊都顯示「0」，卻有一邊標成比較好【該修】已驗證
- ui.js:170 顯示用 `Math.max(p.savings, 0)`，ui.js:272、278 比較用 `leftN: p.savings`（可以是負的）。
- 357 次分岔裡有 133 次兩欄都是「0」，但其中一欄是高亮。
- 改法：比較也用 max(0, …)；或負債直接寫「負債 X 萬」。

## 5. 對照表跟上方說明對不起來【該修】已驗證
- index.html:98「你自己的運氣⋯⋯從那一年起重新擲骰」；index.html:100「其中一種運氣：你原本那一種」；ui.js:248 `runPath(i, alt.k, null)`（salt 是 null，不重擲）。
- 兩句互相矛盾。左欄是玩家自己做的後續抉擇，右欄是系統代選，表上沒標（只有上方框標了）。實測同一個選項讓系統重跑，361 局裡 36 局歲數、22 局家庭就跟玩家實際的一生不一樣，選項還沒換就有差。
- 改法：右欄註明「之後的抉擇系統代選」；左欄改用 `runPath(i, pk.k, null)`，或拿掉 br-note 裡「重新擲骰」那句。

## 6. 分享會帶出真實年紀，畫面沒講【該修】推論
- ui.js:305-306 網址帶 `age`，文字是「1996 年，我出生在⋯」。這個年紀是玩家自己輸入的今年幾歲，分享出去就等於公開出生年。
- 改法：分享鈕旁加一行「連結會帶你填的年紀」，或分享前讓玩家選擇要不要帶。

## 7. 壽命註記只講一半，檢查守門太鬆【小事】已驗證
- ui.js:264「老年的餘命比生命表短一兩年」。實測 65 歲 −1.7 年、40 歲 −1.1 年，但 60 歲前走的比例是 17.4%，生命表是 20.1%（容許 3，只差 0.3 就會擋）。
- check.js:207 只用 `includes('壽命只校準過平均')` 判斷，寫在註解裡也算過。
- 改法：補一句「60 歲前走的比生命表少一些」；守門改成比對 br-luck 那段的實際字串。

## 8. 螢幕閱讀器漏念分享提示，結局頁焦點不見【小事】已驗證
- ui.js:98 announce 只念出生和機率，沒念 shared-note、dv-note，焦點又直接跳到「開始這一生」。
- ui.js:207 只設了 tabindex 沒有 focus，實測結局頁 activeElement 是 BODY。
- 改法：分享進來時把提示句加進 announce；end() 補上 `$('e-h').focus()`。

## 9. from=share 會一直帶下去【小事】已驗證
- ui.js:17-18：從分享連結進來以後，自己再玩幾局，所有「寫下卡住的事」連結都是 `from=share`（實測三個連結都是）。begin.js:11 每次帶 from 就覆蓋，後台記到的是最後一次來源。
- 只要分析時知道 share＝「從分享連結進站」就沒問題，建議在 Account.gs:98 的註解寫清楚。

## 10. 驗證碼沒限制試幾次【小事】推論
- Account.gs:89-93：10 分鐘內 signupFinish 可以無限次猜 6 位數，能拿別人的 Email 搶註冊。
- 改法：CacheService 記錯誤次數，錯 5 次就作廢這組驗證碼。

## 11. 分岔頁同步跑 101 局【小事】已驗證
- ui.js:236 跑 50×2＋1 局，桌機實測 72 ms，node 中位數 51 ms。手機可能卡半秒，期間沒有任何提示。
- 改法：先切到分岔頁顯示「計算中」，再用 setTimeout 跑。

沒問題的部分：dv 版本不同時提示會出現（實測 dv=old）；5 歲前走的局提示和分享文字用同一條界線；分岔前的人生重跑跟原本一模一樣（273/273）；國家抽樣用 2 萬局卡方檢定，結果正常。
