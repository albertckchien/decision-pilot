# 嚴審結論：「再活一次」上線後改善（2026-11-15）

## 這輪做了什麼
用戶同意的 7 件：分岔多跑 50 組運氣種子、第二局起可以跳過抽國家、螢幕閱讀器只念重點、分享連結、壽命校準、漏斗 `from`（前台＋後台）、跟 1in8b 逐項比對（`docs/1in8b比對_2026-11-15.md`）。

## 流程
案卷 → 檢方、辯方 → 18 個角色分開審 → 法官計票（兩票以上才改，修改清單 5 條）→ 照清單改 → 複審（10 條）→ 修 → 獨立重審（11 條，中途碰到額度上限，恢復後接著做完）→ 逐條驗證後修 → `check.js` 和截圖再驗。

## 複審 10 條（全部修了）
「多數」用錯、網站更新提示留到下一局、「朋友的一生」說錯（只分享出生）、快照把資料更新算成引擎改了、條件餘命比法偏（改成照 l(x) 加權）、5 歲界線差一歲、電腦走系統分享沒回饋、配對檢查名不副實（改註解）、健康係數平均算錯範圍、文件沒跟上（backlog 補了漏斗規則和每週重校步驟）。

## 獨立重審 11 條（逐條驗證都成立，全部修了）
- 擋上線：「跳過」第一局就看得到（`.btn` 蓋掉 `hidden`）→ play.css 加 `[hidden] { display: none !important; }`，實測第一局 none、第二局出現、按了直接出生卡。
- 分享網址框一直開著、換局不清；分岔後同一種抉擇只沿用第一次的選法（改成照出現順序，實測 40／40 先「還不想」後「結婚」的人另一條路也結婚了）；兩邊都是 0 卻標比較好；對照表左欄是玩家實際那一生、右欄是系統代選（改成兩欄都系統代選、從原本那組運氣種子出發，標題寫清楚）；分享會帶年紀（加一行說明）。
- 小事：壽命註記補「60 歲前走的比生命表少一些」、check 改成看畫面字串；螢幕閱讀器念分享提示、結局頁焦點；`from=share` 的意思寫進後台註解；驗證碼錯 5 次作廢；分岔頁先顯示「計算中」再算。

## 驗證
- `node play/check.js 1000`：全部通過。5 歲前 7.7%／生命表 7.9%；平均 72.4／72.6 歲；60 歲前 17.4%／20.1%；15、40、65 歲餘命 64.9／64.7、40.8／41.9、19.0／20.7（65 歲超過容許，畫面已註明）。快照、可重現、欄位白名單、國名、網址參數都過。
- `node play/check.js calibrate`：0.7 差 −0.01 歲。
- 無頭瀏覽器（桌機 1280、手機 390）：出生、抉擇、結局、分岔、分享失敗、分享落地（一般、夭折、舊版本）、跳過，0 個 console 錯誤。

## 沒做（觀察或延後）
壽命形狀（60 歲前走得少、老年短）要改重病算法時一起校；分岔後讓骰子對齊（要改引擎）；漏斗報表和分母、註冊頻率限制；1in8b 比對建議的 5 項（名字和自己國家並排、分享圖卡、公開對照表、略過開關、現場感）等用戶決定。

## 結論
前台可以推上公開網站。推上去之後，再問用戶同意推 Apps Script 後台；推完照法官的清單測（`from=play`、`from=share` 各註冊一次，對 API 送 `=HYPERLINK(...)`、超過 12 字、大寫、空值），漏斗才算上線。
